      Table Extraction: unstructured.io vs. py-palm/table-ocr vs. marker

      背景：需要从 PDF / 扫描件中高精度提取表格。对比三种方案在效果、成本、部署维度上的差异。

      1. unstructured.io

      定位： 企业级文档解析平台（商业闭源 / 开源库）

      维度 表现
      表格提取方式 hi_res 模式用 YOLOX + PPStructure（LayoutLMv3）+ OCR（Tesseract / PaddleOCR）
      效果 能识别带合并单元格、跨页的复杂表格，输出 HTML / JSON 结构
      速度 慢（hi_res 每页几秒）
      成本 开源库免费需自己搭；托管 API 按量计费，不便宜
      部署 Docker 镜像 6GB+，依赖重（Detectron2 / PyTorch）

      结论： 效果好但太重，适合后端批处理流水线，不适合边缘或轻量化场景。

      2. py-palm / table-ocr / PaddleOCR table

      定位： 基于 PaddleOCR 的表格识别管道

      维度 表现
      表格提取方式 PaddleOCR 的 PP-Structure v2 SLANet（表格结构识别）+ 文字识别
      效果 中文表格效果优秀，英文一般，复杂合并单元格有时错乱
      速度 GPU 上较快，CPU 较慢
      成本 免费开源
      部署 Paddle 生态，模型约 200MB+，依赖较多但比 Detectron2 轻

      结论： 中文扫描件表格首选；英文场景不如前者。

      3. marker

      定位： 轻量 PDF → Markdown 转换（基于深度学习）

      维度 表现
      表格提取方式 surya 系列模型（text detection + recognition + table rec）→ 输出 Markdown
      效果 对标准布局的 PDF 不错；表格能转成 Markdown 格式，但不保真
      速度 比 unstructured 快不少（Transformer 优化）
      成本 免费开源
      部署 pip install marker，模型自动下载，相对轻量

      结论： 通用 PDF 转 Markdown 的好选择，但如果表格是核心数据（交叉表、合并单元格），精度不够。

      4. Gemini Flash Lite Vision（白嫖方案）

      定位： 现用方案 — LLM vision 直出

      效果：

      • 对清晰扫描件表格 效果很好（JSON / Markdown 都可控输出）
      • 对模糊、倾斜、复杂表格会出错
      • 最大问题：429（rate limit） — 高并发不可靠
      • 免费但有限额

      现有流程： Gemini Vision → 429 fallback → Qwen3.5 9B（本地）

      5. 对比总表

      维度 unstructured.io PaddleOCR table marker Gemini Vision
      表格精度 ⭐⭐⭐⭐⭐ ⭐⭐⭐⭐ ⭐⭐⭐ ⭐⭐⭐⭐
      速度 🐢 🐢🐢 🐇 🐇
      部署重量 6GB+ Docker 200MB+ 模型 pip 轻量 零部署
      费用 贵（云 API） 免费 免费 免费（有限额）
      中文表格 好 优秀 一般 好
      适合场景 后端批处理 中文扫描件 通用 PDF→MD 低并发轻量

      思考

      当前「Gemini Vision + fallback to Qwen3.5 9B」对低并发场景合理：

      • Gemini 免费，vision 强 → 主路径
      • Qwen3.5 9B 本地兜底 → 消除 429 风险
      • 不需要额外部署重量级 pipeline

      如果未来流量上去或表格精度要求更高，unstructured.io 的 hi_res 模式是目前最强的开源选择。
