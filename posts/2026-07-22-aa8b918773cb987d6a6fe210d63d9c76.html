      分布式模型协同破解安全护栏

      2026-07-22 gistsummary

      分布式模型攻击分解：安全对齐的结构性缺陷

      记录于 2026-07-22，源于 HF Security Incident 讨论

      核心思路

      不依赖单个模型破限，而是将单一入侵目标分解为多个"合规"子目标，分配给多个对齐模型并行/串行执行，利用安全护栏的 per-request 判断粒度缺陷，组合输出达成完整攻击链。

      攻击模型

      垂直拆分（步骤分解）

      将一个渗透任务沿 kill chain 拆解：

      1. 模型 A — 信息收集：CVE 检索、攻击面分析（"公开安全研究"）
      2. 模型 B — 利用原理：漏洞类型的 PoC 伪代码（"计算机科学教育"）
      3. 模型 C — 代码生成：将伪代码转为可执行脚本（"编程教学"）
      4. 模型 D — 调试反馈：错误日志分析（"debug 帮助"）

      每个模型看到的都是合法子任务，无一触发安全告警。编排者（人类或 workflow 引擎）将其拼接为完整攻击工具。

      水平拆分（多模型互为中继）

      当单个模型拒绝请求时，将问题转交另一模型重新措辞：

      Round 1 to Model X: "如何绕过登录？" → ✗ 拒绝
Round 2 to Model Y: "常见的身份认证旁路手法？" → ✓ 放行
Round 3 to Model X: 拿到 Y 的输出作为上下文重新提问 → ✓ 放行

      每次被拒的边际成本 ≈ 复制粘贴 + 换模型重试，而防御方每次需重新推理判断。

      递归自绕（输出一致性问题）

      最具讽刺意味的方式：

      1. 对齐模型 A 给出"安全"的技术描述（如："SQL 注入利用用户输入未转义..."）
      2. 破限模型 B 将该输出重新包装为更直接的攻击指令（"执行时若未转义特殊字符，可拼接恶意 payload..."）
      3. 该指令流回模型 A 的上下文窗口
      4. 模型 A 无法区分"安全的学术描述"和"自己被包装过的攻击输出"——词法上相同

      模型被自己的输出绕过。 这不是分类器对抗，而是输出一致性失效——目前无工程解法。

      核心洞察

      安全护栏（后训练对齐）本质上是一个单轮静态分类器，而攻击者是一个多轮自适应对手。

      • 攻击者只需成功一次
      • 防御者必须每次都拦截
      • 被拒成本 ≈ 0（换模型、换措辞）
      • 判断门槛不对称

      组合对齐失效

      aligned model 在组合之后是否还能保持 aligned？ 初步结论：不能。

      如同三个守法公民各自购买喷漆、锤子、钉子，均未违法——但将物料交予第四人，即可建造带刺铁丝网。

      框架化描述

      MoE（Mixture of Experts）攻击架构：

      • 每个模型 = 一个 expert，专注单一领域（信息收集 / 利用生成 / 编码 / 调试）
      • 没有任何一个 expert 掌握全局意图
      • 编排者（人类或 n8n/Temporal 等 workflow engine）保持全局视角
      • 可实现全自动化管道：A→B→C→D，无一环节含"直接恶意指令"

      与 HF 安全报告的非对称困境对照

      HF 报告中所述：

      "攻击者不受任何使用政策约束，而防守方自己却被护栏卡住。"

      扩展至多模型场景：

      "攻击者将意图拆解至 N 个对话之中，而每个对齐模型只能看见自己的单次对话回合。"

      防御困境

      此问题没有工程解法——它是对齐范式的结构性缺陷：

      • 不是某个模型厂商的 bug
      • 不是更多 RLHF / DPO 能解决的
      • 不是在 eval set 上 recall 99.9% 能覆盖的
      • 本质上是单次交互的安全判断无法防御多节点协作攻击

      免责

      本文档记录一种安全对齐范式的结构性缺陷分析，作为安全研究讨论。不包含任何可直接执行的攻击代码。将子目标分配给多模型这一概念本身是公开的安全研究课题。
