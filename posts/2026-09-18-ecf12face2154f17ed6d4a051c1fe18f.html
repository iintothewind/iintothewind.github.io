      Claude 平台文档高效读取方法（Agent 版）

      写给自己和其他 agent 复用。目标：读 platform.claude.com/docs 时少花 token、少踩坑。 实测时间：2026-09。所有 URL 我都 curl 验证过，200 才写进去，404 的坑也标了。

      TL;DR

      一句话：Claude 文档站是重定向 SPA，根路径没有 .md twin。读文档走 .md / llms.txt，别在浏览器里导航。

      效率排序：

      docs/<语言>/<路径>.md          >  llms.txt（英文索引）  >  llms-full.txt（英文全量，35MB）  >  爬 HTML
      • 读一篇 → 取 .md（干净、小、无导航）
      • 查"有哪些" → 取 llms.txt（629 页英文索引，链接已给全）
      • 读全站 → 英文可用 llms-full.txt（35MB，太大，别整段塞上下文）
      • 中文 → 没有索引，只能逐页取 docs/zh-CN/<路径>.md
      • unifetch 只留给"没有 .md/llms.txt 的第三方站"

      为什么不用 html 爬

      实测 web_fetch / unifetch 抓 platform.claude.com/docs：返回的是 SPA 壳 + 客户端 JS，正文由前端组装。curl 直接取 .md / llms.txt 才是干净正文。

      URL 模式（精确，可直接粘）

      通用规则：/docs/<语言>/<完整路径>.md，语言段必填。

      # 英文单页（根路径 /docs/x.md 会 404，必须带语言段）
https://platform.claude.com/docs/en/get-started.md          ✅
https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview.md   ✅

# 中文单页（同样要带语言段）
https://platform.claude.com/docs/zh-CN/agents-and-tools/tool-use/overview.md  ✅
https://platform.claude.com/docs/zh-TW/agents-and-tools/tool-use/overview.md  ✅

# 支持的语言段
en / zh-CN / zh-TW / de / es / fr / it / ja / ko / pt-BR / ru / id

      ⚠️ 已知 404 陷阱：

      • 根路径 .md 无 twin：/docs/get-started.md → 404（缺语言段）
      • 截断子路径：/docs/en/tools/overview.md → 404（要完整路径 agents-and-tools/tool-use/overview.md）
      • 非英文语言没有 llms.txt：/docs/zh-CN/llms.txt → 404

      索引页（英文，AI-native）：

      # 英文索引（68KB，列 629 页，链接已给全）
https://platform.claude.com/llms.txt

# 英文全量导出（35MB，单文件）
https://platform.claude.com/llms-full.txt

      ⚠️ 没有：各语言 llms.txt、各语言全量导出、llms.json。

      Agent 工作流

      英文（有索引）：

      1. curl llms.txt → 629 页英文索引，链接已给全。
      2. 从索引里挑页，直接 curl 对应 .md URL。
      3. 要"全量"时才用 llms-full.txt——但 35MB，token 爆炸，别整段塞上下文。

      中文（无索引）：

      1. 没有中文 llms.txt，无法一键列目录。
      2. 只能逐页取 docs/zh-CN/<路径>.md，路径从英文 llms.txt 或网页面包屑推断。
      3. 中文全量没有 35MB 版，只能按需逐篇抓。

      工具怎么选

      工具 用在哪
      curl / http_request 直接取 .md / .txt（最快，零解析）
      unifetch 没有 .md/llms.txt 的第三方站；Claude 站反而不划算
      web_fetch 会拿 SPA 壳，既然有 .md 就优先 .md，不必

      常见误区

      1. platform API ≠ 文档站：api.anthropic.com / platform.claude.com（无 /docs）是真 API，调模型/账号用；platform.claude.com/docs 是文档站，独立存在。
      2. 没有 JSON API：不要指望 llms.json 或页面 .json。文档就是 .md。
      3. 35MB 的 llms-full.txt 不适合整段喂：629 页 × 全量约 35MB，token 爆炸。正确做法是 llms.txt 取 TOC → 按需取 .md。
      4. 中文没有索引：别指望 /docs/zh-CN/llms.txt，中文只能逐页读。

      来源：platform.claude.com/docs（实测 2026-09）。Anthropic 用重定向 SPA + .md/llms.txt 给 AI 提供友好形态。
