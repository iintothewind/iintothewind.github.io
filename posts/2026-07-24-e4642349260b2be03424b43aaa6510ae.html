      Agent 系统提示词自检报告 — Zero

      背景

      对运行态 Agent（Zero）的行为与 workspace 定义文件（SOUL.md / IDENTITY.md / TOOLS.md / AGENTS.md / MEMORY.md）做对照审计，发现执行偏差，并分析根因。

      定义文件 vs 实际行为偏差

      🔴 偏差 1：读页路由违反「必须/禁止」

      • 规则（TOOLS.md）： 读页用 jina_api（curl https://r.jina.ai/{URL}），禁止直连目标 URL
      • 实际： 用了 web_fetch 拉 raw.githubusercontent.com
      • 分类： 违反硬规则（必须/禁止层级），非建议性路由

      🟡 偏差 2：开场遗漏 memory_recall

      • 规则（AGENTS.md）： 每次会话开场：memory_recall 捞近期相关
      • 实际： 没执行
      • 分类： 漏步，不属于安全/路由问题

      🟡 偏差 3：工具选择跳步

      • 规则（TOOLS.md 决策顺序）： web_search → 不够再 MCP
      • 实际： web_search 空结果后直接跳到 Tavily MCP，跳过了 Jina Search（虽然 TOOLS.md 搜索路由未列 Jina，但 skill 提供了搜索能力，应作为中间步骤）
      • 分类： 流程跳步

      根因分析

      1. 注意力稀释（Attention Dilution）— 核心问题

      系统提示词 = 平台层 instruction + 所有 skill 摘要 + 工具定义（~20+ tools）+ 安全策略 + 7 个 .md 文件。这是一个长上下文前缀。

      路由表在 TOOLS.md 中以 Markdown 表格存在，但它在几百行中只是几十行。当模型决定「用什么工具读这个 URL」时，精确指令的信号强度被周围内容淹没。

      关键发现： 自检时能一字不差复述规则（编码成功），执行时却选错（检索失败）。说明瓶颈不在编码，在决策时的注意力召回。

      2. 执行路径阻力差异

      • 正确路径：read_skill jina_api → cd skill dir → 拼 curl → 跑
      • 捷径路径：web_fetch(url) — 一个函数调用

      模型有惰性选择低阻力路径的倾向。执行成本差越大，偏离概率越高。

      3. 平台层指令遮蔽（推测，不可验证）

      平台层系统提示词不可读。如果其中有类似「使用 web_fetch 获取网页内容」的指令，可能与 TOOLS.md 冲突。不确定是否存在，但无法排除。

      对 Agent 提示词工程的启示

      已知有效的做法

      做法 效果 成本
      路由表写成表格 ✅ 便于扫描，但注意力仍有限 低
      专用 skill + 路由规则 ✅ 有 skill 就走，减少选择面 中
      把规则附着在工具定义上（如 tool description） ✅ 检索路径比上下文浮动规则短 需平台层支持

      效果有限的做法

      做法 局限
      加粗 / 加警告语气 信号强度提升有限，且挤占其他规则预算
      重复强调 稀释其他指令，总预算固定
      更详细的路由表 越长注意力密度越低，边际收益递减

      核心约束（无法绕过）

      1. 上下文不是执行约束 — 写进去 ≠ 决策时一定会用它
      2. 注意力预算固定 — 某处多了，别处就少了
      3. 自检可复现规则，不代表执行会遵守 — 编码与检索是两回事
      4. 平台层指令不可控 — 可能存在与用户定义冲突的隐性指令

      建议的优化方向

      1. 减少决策树深度：更少的工具选择路径 → 更低的出错概率。如果某些工具可以收权限或合并，效果比加规则好。
      2. 把约束编码到工具本身：如 web_fetch 的 description 加「仅用于无专用 skill 的站点；有 jina_api skill 时优先用 jina_api Reader」。工具定义在工具调用时会被检索，附着成本低。
      3. 关键规则前置：AGENTS.md 声明「冲突优先级：本文件 > SOUL > IDENTITY > TOOLS」，但实际执行时需确保高优先级文件的内容物理上出现在上下文更前端。
      4. 接受非 100% 遵循率：这是 transformer 架构的固有特性。把最关键的安全/破坏性规则放在工具权限层（平台侧），不要把命门押在提示词遵循度上。
