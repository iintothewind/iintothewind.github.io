      关于 "leaked-llm-prompts" 那个 repo 的一点看法

      看到 Eversmile12/leaked-llm-prompts 拿了 160+ stars，点进去看完的感受：矿挖出来了，但矿石没洗直接堆那了。

      不是什么秘密

      这个 repo 的实质是：从 claude.ai 的网页端/API 响应里，把注入的 system prompt 文本 dump 出来拼成一个文件。技术上就是抓个包或者读一下 API 返回，零逆向工程、零破解。能拿到不意外，意料之中的是拿了也就拿了，没有后续。

      真正缺什么

      一份有价值的 prompt leak 分析，至少应该覆盖这四个维度，但这个 repo 一个都没碰：

      1. 提取方法（透明可复现）

      怎么拿到的？是 DOM 解析、API 拦截、还是工程模式？写清楚别人能重复验证，甚至有心思的人能做成自动化 diff 工具追踪 prompt 变更。藏着掖着就没意思了。

      2. 提示词工程结构（架构价值）

      Anthropic 怎么组织百万 token 级 prompt 系统？从文件里能清楚看到模块拆分粒度——# claude_behavior 是核心人格，# memory_filesystem、# search_instructions、# computer_use 都是独立模块，明显是按条件加载的。运行时不会全量塞 135k（~34k tokens）进上下文，那太蠢了。但真正的架构设计——模块触发条件、优先级覆盖规则、工具 schema 的注入策略——这些一句没提。

      3. 加载机制（成本与性能反推）

      135k 一次性加载不现实。合理的推测是：

      • 核心固定加载：claude_behavior（角色、安全、合规、语气）——这部分最精简，始终在 prompt 里
      • 按需条件注入：memory_filesystem 只在有记忆操作时插入，search_instructions 只在 web_search 被调用时加载
      • 工具 schema 走 API 声明：30 个工具的完整 JSON schema（占了文件 60%+ 的体积）是通过 /messages API 的 tools 参数传入的 function calling 定义，不是硬塞在系统 prompt 正文里

      这些反推能揭示 Anthropic 的推理成本优化策略，但 repo 只给了原材料。

      4. 设计思路反推（真正的洞察）

      文本背后藏着大量架构决策：

      • privacy_requirements 里 36 行的详尽黑名单——说明 Anthropic 对记忆系统的隐私风险做过完整的红队推演
      • "The test for every line: did the user say this?"——这条规则反映了他们对记忆幻觉的明确防范设计
      • refusal_handling 里对儿童安全的极端保守策略（"if Claude finds itself mentally reframing a request to make it appropriate, that reframing is the signal to REFUSE"）——这条规则本身就是一个很好的安全对齐案例

      这些才是真正有分析价值的东西，但 repo 里一个字没有。

      一点感想

      GitHub stars 从来不等于质量，它等于注意力杠杆。"leaked"+"Claude Opus 5"这两个词凑一起，流量已经锁定了，168 stars 里大半是点进来看一眼的路人，和内容深度无关。

      真正有工程价值的东西——比如一个结构清晰的 skill 框架、一组可复用的 API 封装、一个数据管线——反而因为需要用户真正去用才能体会到价值，传播门槛天然高。

      没什么好不平衡的，只是平台机制和文化如此。这东西放在那当个原始资料参考还行，但给它标榜成什么重大发现就过了。
