      DGX Spark 静默死机：长 Prefill 与 nvidia-580-open

      DGX Spark（GB10，128GB 统一内存）跑大模型长上下文 prefill（社区复现约 69K+ token）时，可能整机瞬间卡死：无 panic、无清晰 OOM、看门狗不触发，往往只能拔电。这和「推理进程挂了但还能 SSH」不是一类问题。

      原因

      部分出厂镜像默认是开源 GPU 内核模块：

      modinfo nvidia | grep filename
cat /proc/driver/nvidia/version

      若路径含 nvidia-580-open，或 NVRM 写着 Open Kernel Module，即属易感配置。社区多台对比结论：该模块在统一内存高压下的分配失败路径可能触发内核活锁；换成同版本专有模块后现象明显缓解，性能通常无明显回退。

      短请求不易触发；偶发超长 prefill 更容易踩中。拉长框架超时、降并发只能减少频率，不能代替换驱动。

      补丁

      从 到
      nvidia-driver-580-open nvidia-driver-580
      linux-modules-nvidia-580-open-nvidia-hwe-24.04 linux-modules-nvidia-580-nvidia-hwe-24.04

      保持同一 580 系列，勿顺便跨大版本升级（驱动需与 OTA 固件配对）。先确认源里有包：

      apt-cache policy nvidia-driver-580 nvidia-driver-580-open
apt-cache policy linux-modules-nvidia-580-nvidia-hwe-24.04

      操作

      # 1. 留档并停掉所有大模型负载
modinfo nvidia | grep -E '^(filename|version|license):'
cat /proc/driver/nvidia/version
docker stop <your-llm-containers...>

# 2. 换同版本专有模块
sudo apt update
sudo apt install -y nvidia-driver-580 linux-modules-nvidia-580-nvidia-hwe-24.04
# 如有残留：sudo apt purge -y nvidia-driver-580-open linux-modules-nvidia-580-open-nvidia-hwe-24.04

# 3. 重启
sudo reboot

      确认

      modinfo nvidia | grep filename
cat /proc/driver/nvidia/version
nvidia-smi

      通过：filename 为 .../nvidia-580/nvidia.ko（无 open）；NVRM 为 NVIDIA UNIX Kernel Module（无 Open）；nvidia-smi 正常。

      可选：专有模块下再跑一次长 prefill。若仍整机静默死机，需另查电源/固件，不能再单怪 open 模块。

      回滚：

      sudo apt install -y nvidia-driver-580-open linux-modules-nvidia-580-open-nvidia-hwe-24.04
sudo reboot
