      Cloudflare 开发者文档高效读取方法（Agent 版）

      写给自己和其他 agent 复用。目标：读 developers.cloudflare.com 时少花 token、少踩坑。 实测时间：2026-09。所有 URL 我都 curl 验证过，200 才写进去，404 的坑也标了。

      TL;DR

      一句话：Cloudflare 是"多产品 + OpenAPI"站，结构最丰富。Workers Runtime API 有完整 OpenAPI JSON（25.5MB，2207 paths，11035 operations），机器可读首选 jq 查询；各产品指南用 <产品>/llms.txt；单页用 Accept: text/markdown 隐藏技巧取 Markdown。

      效率排序：

      openapi.json (jq 查 Workers API)   >  <产品>/llms.txt (索引)   >  Accept: text/markdown (单页)   >  爬 HTML
      • Workers Runtime API（查接口/参数） → /openapi.json + jq（25.5MB，2207 paths，11035 operations）
      • 读某个产品指南 → <产品>/llms.txt（每个产品有自己的索引，官方推荐）
      • 读单篇 → curl -H "Accept: text/markdown" <页面URL>（隐藏技巧，任意页面返回 Markdown）
      • wrangler CLI → 用官方 skill（wrangler 那个确实好用，文档站反而是次要的）

      四种形态（都实测）

      形态 URL 状态 用途
      OpenAPI JSON /openapi.json ✅ 25.5MB Workers Runtime API 完整机器可读参考
      根索引 /llms.txt ✅ text/plain 所有产品入口
      产品索引 <产品>/llms.txt ✅ 各产品独立 单产品文档导航（官方推荐）
      Markdown 单页 任意页面 + Accept: text/markdown ✅ 隐藏技巧 取单篇正文
      .md twin <页面>.md ❌ 404 不存在
      GitHub raw — ❌ 404 docs 不提交源码

      URL 模式（精确，可直接粘）

      1. Workers Runtime API（机器可读，用 jq）

      # 取整个 spec（25.5MB，先缓存到本地）
curl -sL https://developers.cloudflare.com/openapi.json -o openapi.json

# 列所有 path
jq -r '.paths | keys_unsorted[]' openapi.json

# 数 operations
jq '[.paths[]? | (.get,.post,.put,.delete,.patch)] | length' openapi.json   # 11035

# 查某个 path 的所有方法 + summary
jq '.paths["/accounts"] | to_entries | map({method: .key, summary: .value.summary})' openapi.json

# 查某个 operation 的参数 schema
jq '.paths["/accounts"] | .get.parameters' openapi.json

      2. 根索引（所有产品入口）

      https://developers.cloudflare.com/llms.txt   →  每个产品链接到自己的 llms.txt

      3. 产品索引（官方推荐，单产品导航）

      # Workers（最常用）
https://developers.cloudflare.com/workers/llms.txt   →  526 行，链接到各页 .md

# 其他产品都同理
https://developers.cloudflare.com/cache/llms.txt
https://developers.cloudflare.com/dns/llms.txt
https://developers.cloudflare.com/api-shield/llms.txt

      4. 单页（隐藏技巧：Accept: text/markdown）

      # 关键：不带 .md 后缀，但发 Accept: text/markdown header
curl -s -H "Accept: text/markdown" https://developers.cloudflare.com/workers/
# → 200, text/markdown, 6916B，干净正文

# 嵌套路径同理
curl -H "Accept: text/markdown" https://developers.cloudflare.com/workers/tutorials/hello-world/

      ⚠️ 已知 404 陷阱：

      • .md twin：/workers/index.md 直接 curl 会 404（需要 Accept: text/markdown header）
      • 错误路径：/workers/tutorials/hello-world/ → 404（真实路径在 llms.txt 里）

      Agent 工作流

      查 Workers Runtime API 接口（最常见）：

      1. curl -L https://developers.cloudflare.com/openapi.json -o openapi.json（缓存一次，25.5MB）
      2. jq 定位 path / operation / 参数 / schema
      3. 需要说明性文字时，curl -H "Accept: text/markdown" <页面URL> 取正文

      读某个产品指南：

      1. curl -L <产品>/llms.txt → 该产品文档索引
      2. 从索引挑页，curl -H "Accept: text/markdown" <页面URL> 取正文

      工具怎么选

      工具 用在哪
      curl + jq Workers API 首选。openapi.json + jq 定位接口/参数，零 HTML 解析
      curl -H "Accept: text/markdown" 取单篇正文（官方隐藏技巧，比 .md 后缀更通用）
      web_fetch 兜底，但不如 curl + header 干净
      unifetch 不划算

      常见误区

      1. 别找 .md twin：Cloudflare 页面 .md 后缀 curl 直接 404。要用 Accept: text/markdown header。
      2. 别整段喂 openapi.json（25.5MB）：11035 个 operation，token 爆炸。正确做法：先 jq 定位 path/operation，再针对性查字段。
      3. wrangler 优先用官方 skill：CF 的 wrangler CLI 有官方 skill，比翻文档站更高效。文档站主要给"理解接口/指南"用。
      4. api-catalog 不是完整目录：/.well-known/api-catalog 只是个 linkset（指向 openapi.json），别指望它是结构化 API 目录。

      来源：developers.cloudflare.com（实测 2026-09）。Cloudflare 用 OpenAPI JSON + Accept: text/markdown + 各产品 llms.txt 给 AI 提供友好形态。
