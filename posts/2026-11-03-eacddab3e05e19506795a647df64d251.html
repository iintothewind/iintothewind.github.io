      DuerOS (Xiaodu) 智能音箱：root 后解除系统限制的完整经验

      设备：Xiaodu NV2001，Rockchip rk3326，Android 8.1.0 (API 27)，Magisk 26.1 目标：在已有 root 的前提下，让第三方应用（F-Droid、Termux 等）能正常安装、开机自启、启动。

      百度为什么这么做

      百度 DuerOS 不是普通 Android，它把设备当作自己的封闭内容平台来做管控。这套限制的目的不是"安全防护"，而是让设备只能按百度的方式使用，用户没有自主权。

      黑名单的真实含义

      百度桌面（com.baidu.launcher）维护一份包名黑名单，开机时推入系统（ActivityStackMonitor.setBlockingList），之后定期刷新。黑名单里的包名启动会被拦截（返回错误码 -88），用户无法直接打开它们。

      看起来矛盾的是：黑名单里既有百度自己的 app（猜谜、桌面宠物、作业帮），也有内容合作方（BabyBus、洪恩、iHuman、喜马拉雅儿童），还有竞品（抖音、快手、B站、优酷、爱奇艺、芒果TV、腾讯视频）。

      实际上这三类都符合同一个逻辑：凡是被列入黑名单的 app，必须以百度桌面提供的 bot 入口方式访问，不允许用户直接启动原始 Activity。 百度桌面对这些包名有一套代理接管机制（VideoBotProxy、VideoEntryHelper），由桌面主动拉起、走自己的 UI 集成。屏蔽原始启动路径是为了强制用户走百度的入口——竞品被屏蔽是商业排他，合作方被屏蔽是因为百度要用自己的 bot 包装它们（带广告/会员分成），百度自己的 app 被屏蔽是因为功能已经迁移进桌面本体，旧的独立 APK 版本要防止绕过新流程。

      换句话说：黑名单是"百度管控名单"，不是"禁止名单"。加入黑名单意味着"这个 app 受我管控，只能用我给你的方式用"。

      对第三方 app 的影响

      这套管控逻辑对第三方 app（F-Droid、Termux 等）同样生效，因为百度在 framework 层把整套限制写进了系统代码，而不是只针对特定包名：

      • REQUEST_INSTALL_PACKAGES 改成 signature|privileged：第三方 app 无法调用安装器
      • BOOT_COMPLETED 不发给非系统应用：第三方 app 无法开机自启
      • ActivityRedirection：第三方 app 打开设置会被转到百度的设置页
      • ActivityStackMonitor：黑名单机制会拦截特定包名，第三方 app 不在名单里暂时不受这条影响，但管控机制本身是系统级的
      • VideoBotStackUtils：会杀进程，对不在白名单里的视频 app 生效

      百度这么做的动机：设备是百度的内容分发渠道，第三方 app 会绕过百度的内容生态、广告分成和语音交互入口。root 是用户自己的权利，但百度的固件设计假设设备永远只能按它的方式使用。

      具体限制列表

      • REQUEST_INSTALL_PACKAGES 权限从 AOSP 的 signature|appop 改为 signature|privileged，只有特权系统应用能调用安装器
      • BroadcastQueue 不向非系统应用发送 BOOT_COMPLETED，导致 Termux:Boot 等开机自启失效
      • ActivityRedirection：非系统应用打开 com.android.settings 会被重定向到百度自己的设置页
      • ActivityStackMonitor：百度桌面开机时推送一份包名黑名单（抖音、B站、芒果、优酷、腾讯视频等），名单里的应用启动返回 -88
      • VideoBotStackUtils.killAllVideoBot：杀掉不在白名单里的视频应用进程

      解决方案：Magisk 模块

      创建一个 Magisk 模块，把需要的应用提升为特权系统应用，并清空黑名单。

      module.prop

      id=duer_unblock
name=DuerOS Unblock
version=v1
versionCode=1
author=local
description=Promote selected apps to privileged system apps and clear the DuerOS activity blocking list.

      service.sh（开机清空黑名单）

      #!/system/bin/sh
until [ "$(getprop sys.boot_completed)" = 1 ]; do sleep 5; done
sleep 60
while true; do
  uid=$(pm list packages -U com.baidu.launcher | grep -w 'com.baidu.launcher' | sed 's/.*uid://')
  [ -n "$uid" ] && /sbin/su "$uid" -c 'service call duer 36 i32 0' >/dev/null 2>&1
  sleep 600
done

      原理：IDuerService.setBlockingPackages（binder 事务码 36）只接受百度签名的调用方。通过 /sbin/su <uid> 以百度桌面的 uid 执行，签名校验通过，传入空列表即可清空黑名单。

      add-priv-app.sh（添加特权应用）

      #!/system/bin/sh
MOD=${0%/*}
for pkg in "$@"; do
  apk=$(pm path "$pkg" | grep 'base.apk' | head -n 1 | sed 's/^package://')
  if [ -z "$apk" ]; then echo "$pkg: not installed"; continue; fi
  dir="$MOD/system/priv-app/$pkg"
  mkdir -p "$dir"
  cp "$apk" "$dir/$pkg.apk"
  chmod 755 "$dir"; chmod 644 "$dir/$pkg.apk"
  chcon -R u:object_r:system_file:s0 "$MOD/system"
  echo "$pkg: added ($apk), reboot to apply"
done

      用法：sh /data/adb/modules/duer_unblock/add-priv-app.sh org.fdroid.fdroid com.termux com.termux.boot

      安装步骤

      1. 把模块目录放到 /data/adb/modules/duer_unblock/
      2. 执行 add-priv-app.sh 添加需要的应用
      3. 重启

      重启后，这些应用会变成 SYSTEM PRIVILEGED，REQUEST_INSTALL_PACKAGES 自动 granted，BOOT_COMPLETED 也能正常接收。

      SSH 自启

      Termux 安装后，通过 Termux:Boot 实现开机自启 sshd：

      mkdir -p ~/.termux/boot
printf '#!/data/data/com.termux/files/usr/bin/sh\ntermux-wake-lock\nsshd\n' > ~/.termux/boot/start-sshd
chmod +x ~/.termux/boot/start-sshd

      Termux:Boot 需要从 GitHub 下载（与 Termux 签名一致），装好后打开一次触发注册。

      注意事项

      • 安装界面限制：百度把 REQUEST_INSTALL_PACKAGES 的 permission level 改成了 signature|privileged，安装器的检查永远过不了。特权应用也一样。如果应用的 targetSdk ≥ 26，用「打开 APK」的方式安装仍然会失败。 workaround：用 targetSdk < 26 的文件管理器（如 ES 文件浏览器），或直接用 adb install / pm install。
      • Magisk 授权：Termux 需要在 Magisk 里手动授权 root。
      • 恢复：出问题时在 Magisk 里关掉模块，或 rm -rf /data/adb/modules/duer_unblock 再重启。adbd 开机很早就以 root 运行，可以救砖。
      • 黑名单会刷新：百度桌面会定期重新推送黑名单，所以 service.sh 每 10 分钟清一次。

      国内网络与包管理器配置

      F-Droid 镜像

      F-Droid 默认源在国外，国内基本拉不下来。在 F-Droid 里：设置 → 存储库 → 添加清华镜像 https://mirrors.tuna.tsinghua.edu.cn/fdroid/repo，再把官方源关掉。

      Termux 镜像

      装好 Termux 后先执行 termux-change-repo，选清华或中科大的镜像，否则 pkg install 也会很慢。

      ADB 持久化

      开启网络 ADB 后，执行 setprop persist.adb.tcp.port 5555，重启后也会保留这个设置。

      Magisk 授权

      Termux 需要在 Magisk 里手动授权 root（超级用户页 → 找到 Termux → 开关打开）。F-Droid 也可以授权 root（如果需要）。

      设备信息

      • SoC: Rockchip rk3326 (armv8l, 32-bit)
      • Android: 8.1.0 (API 27)
      • Magisk: 26.1
      • SELinux: permissive (boot 时)
      • ADB: 通过 setprop service.adb.tcp.port 5555 + stop adbd; start adbd 开启网络 ADB
