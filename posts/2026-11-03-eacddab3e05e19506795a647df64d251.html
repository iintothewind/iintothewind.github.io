      DuerOS (Xiaodu NV2001) root 后解除系统限制

      设备

      项 值
      型号 / ROM NV2001，DuerShow_RK3326_v1.67.1
      SoC Rockchip rk3326，armv8l 32-bit（APK 需带 armeabi-v7a）
      Android 8.1.0 (API 27)
      root Magisk 26.1，SELinux permissive
      访问 ssh duos（Termux sshd，Termux:Boot 自启）→ su -c；网络 ADB 5555

      百度为什么限制你安装App

      百度 DuerOS 不是普通 Android，它把设备当作自己的封闭内容平台来做管控。这套限制的目的不是"安全防护"，而是让设备只能按百度的方式使用，用户没有自主权。

      黑名单的真实含义

      百度桌面（com.baidu.launcher）维护一份包名黑名单，开机时推入系统（ActivityStackMonitor.setBlockingList），之后定期刷新。黑名单里的包名启动会被拦截（返回错误码 -88），用户无法直接打开它们。

      看起来矛盾的是：黑名单里既有百度自己的 app（猜谜、桌面宠物、作业帮），也有内容合作方（BabyBus、洪恩、iHuman、喜马拉雅儿童），还有竞品（抖音、快手、B站、优酷、爱奇艺、芒果TV、腾讯视频）。

      实际上这三类都符合同一个逻辑：凡是被列入黑名单的 app，必须以百度桌面提供的 bot 入口方式访问，不允许用户直接启动原始 Activity。 百度桌面对这些包名有一套代理接管机制（VideoBotProxy、VideoEntryHelper），由桌面主动拉起、走自己的 UI 集成。屏蔽原始启动路径是为了强制用户走百度的入口——竞品被屏蔽是商业排他，合作方被屏蔽是因为百度要用自己的 bot 包装它们（带广告/会员分成），百度自己的 app 被屏蔽是因为功能已经迁移进桌面本体，旧的独立 APK 版本要防止绕过新流程。

      换句话说：黑名单是"百度管控名单"，不是"禁止名单"。加入黑名单意味着"这个 app 受我管控，只能用我给你的方式用"。

      对第三方 app 的影响

      这套管控逻辑对第三方 app（F-Droid、Termux 等）同样生效，因为百度在 framework 层把整套限制写进了系统代码，而不是只针对特定包名：

      • REQUEST_INSTALL_PACKAGES 改成 signature|privileged：第三方 app 无法调用安装器
      • BOOT_COMPLETED 不发给非系统应用：第三方 app 无法开机自启
      • ActivityRedirection：第三方 app 打开设置会被转到百度的设置页
      • ActivityStackMonitor：黑名单机制会拦截特定包名，第三方 app 不在名单里暂时不受这条影响，但管控机制本身是系统级的
      • VideoBotStackUtils：会杀进程，对不在白名单里的视频 app 生效

      百度这么做的动机：设备是百度的内容分发渠道，第三方 app 会绕过百度的内容生态、广告分成和语音交互入口。root 是用户自己的权利，但百度的固件设计假设设备永远只能按它的方式使用。

      百度的限制与对策

      限制 机制 对策
      第三方应用不能调用安装器 REQUEST_INSTALL_PACKAGES 被改为 signature|privileged 提升为 priv-app（add-priv-app.sh）
      打开 APK 时弹 toast「该应用来源不合法…请到小度应用中心…」 PackageInstaller 的 InstallStart 对 targetSdk ≥ 26 的来源检查 appop 权限，权限已不是 appop，检查永远失败 vdex 补丁（见下文）
      开机自启失效 BroadcastQueue 不向非系统应用发 BOOT_COMPLETED 提升为 priv-app
      打开设置被重定向 ActivityRedirection 把 com.android.settings 转到百度设置页 预先 appops set，绕开设置页
      黑名单应用启动返回 -88 百度桌面推送 ActivityStackMonitor.setBlockingList 并定期刷新 service.sh 每 600s 清空
      静默推送应用 DuerShowOTA（com.baidu.duer.ota）按云端 UpgradeCmd 安装 com.baidu.edgemanager（PCDN 节点） .replace 遮掉 OTA，service.sh 每 30s 卸载 com.baidu.edge*
      杀视频进程 VideoBotStackUtils.killAllVideoBot 未处理

      service.sh

      #!/system/bin/sh
until [ "$(getprop sys.boot_completed)" = 1 ]; do sleep 5; done

# 兜底：DuerShowOTA 已遮掉，若仍有 com.baidu.edge* 出现则卸载
(
  while true; do
    for d in /data/app/com.baidu.edge*; do
      [ -d "$d" ] || continue
      pkg=${d##*/}
      pm uninstall "${pkg%%-*}" >/dev/null 2>&1   # 目录名为 <pkg>-<base64>，base64 可能含 '-'
    done
    sleep 30
  done
) &

# IDuerService.setBlockingPackages (事务码 36) 只接受百度签名的调用方 → 以 launcher uid 调用，传空列表
sleep 60
while true; do
  uid=$(pm list packages -U com.baidu.launcher | grep -w 'com.baidu.launcher' | sed 's/.*uid://')
  [ -n "$uid" ] && /sbin/su "$uid" -c 'service call duer 36 i32 0' >/dev/null 2>&1
  sleep 600
done

      add-priv-app.sh

      #!/system/bin/sh
MOD=${0%/*}
for pkg in "$@"; do
  apk=$(pm path "$pkg" | grep 'base.apk' | head -n 1 | sed 's/^package://')
  if [ -z "$apk" ]; then echo "$pkg: not installed"; continue; fi
  dir="$MOD/system/priv-app/$pkg"
  mkdir -p "$dir"
  cp "$apk" "$dir/$pkg.apk"
  chmod 755 "$dir"; chmod 644 "$dir/$pkg.apk"
  chcon -R u:object_r:system_file:s0 "$MOD/system"
  echo "$pkg: added ($apk), reboot to apply"
done

      用法：sh $MOD/add-priv-app.sh org.fdroid.fdroid com.termux com.termux.boot，然后重启。重启后这些应用是 SYSTEM PRIVILEGED，能收到 BOOT_COMPLETED。

      安装器补丁（PackageInstaller vdex）

      被拦截的代码在 InstallStart.onCreate（AOSP 8.1 原样）：

      else if (targetSdkVersion >= 26 && !declaresAppOpPermission(originatingUid, "android.permission.REQUEST_INSTALL_PACKAGES"))
    mAbortInstall = true;   // → toast
      • APK 里没有 dex，编译过滤器是 quicken，代码在 oat/arm/PackageInstaller.vdex 里由解释器执行。
      • 补丁：vdex 偏移 0xe8798 处 13 0e 1a 00（const/16 v14, 26）改为 13 0e ff 7f（32767），后面紧跟 34 ed dd ff（if-lt v13, v14）。代码长度不变；dex checksum 不需要修复。
      • 补丁后 sha256：2b9056b430dd21fcca611127294df39ad637b4bc9310e7b1bb2c05b3069fb6c1。
      • 效果：所有来源都交给 PackageInstallerActivity.handleUnknownSources()，按 OP_REQUEST_INSTALL_PACKAGES appop 判断。
      D=$M/system/priv-app/PackageInstaller/oat/arm
mkdir -p $D && cp PI.patched.vdex $D/PackageInstaller.vdex && chmod 644 $D/PackageInstaller.vdex
chcon -R u:object_r:system_file:s0 $M/system
rm -f /data/dalvik-cache/arm/system@priv-app@PackageInstaller@PackageInstaller.apk@classes.*   # 缓存优先于 /system，必须删
appops set org.fdroid.fdroid REQUEST_INSTALL_PACKAGES allow   # 每个安装来源都要设置；ES/via 由 /data/adb/service.d/startup 设置
reboot
      • 验证：su 2000 -c "am start -a android.intent.action.VIEW -t application/vnd.android.package-archive -d file:///data/local/tmp/x.apk"，应出现 PackageInstallerActivity 确认页，而不是 E InstallStart: Requesting uid ... needs to declare permission。
      • 恢复：rm -rf $D/../..（即 $M/system/priv-app/PackageInstaller）后重启。
      • pm install / adb install 不经过 PackageInstaller，始终可用。

      Termux 插件

      • Termux 是 GitHub 版（0.119.0-beta.3，签名 db86cf3c，sharedUserId=com.termux），插件必须用 GitHub 版。
      • F-Droid 版是 F-Droid 签名，会报 INSTALL_FAILED_SHARED_USER_INCOMPATIBLE。不要在 F-Droid 里安装或更新 Termux 系列。
      pm install -r termux-api-app_v0.53.0+github.debug.apk   # GitHub termux/termux-api，核对 checksums-sha256.txt
pkg install termux-api && termux-wifi-connectioninfo    # 返回 JSON 即正常

      更新预装应用

      1. 先比对签名：dumpsys package <pkg> | grep signatures。
      2. 签名一致：pm install -r new.apk，作为 UPDATED_SYSTEM_APP 安装，保留 priv 属性、uid、Magisk 授权和组件规则。pm uninstall <pkg> 回退到 /system 里的版本。
      3. 签名不一致：先 .replace 遮掉系统版本，再全新安装。uid 会变，要重新授权（magisk --sqlite "SELECT * FROM policies"）。

      已执行：Blocker（com.merxury.blocker，uid 10025）从 0.1.42-beta 升级到 2.0.6447（GitHub lihenggui/blocker，foss 版，签名 8d68bf0e，与旧版一致）。启动类是 .MainActivity；首页默认不显示系统应用。

      恢复 / 救砖

      • 在 Magisk 里关掉模块，或 rm -rf $M 后重启。
      • adbd 开机很早就以 root 运行，可以用来救砖。

      调试要点

      • 先复现：logcat 缓冲很小，重启就清空。按 logcat -c → 触发 → logcat -d 的顺序做。toast 在触发后约 1 秒用 screencap -p 截图。
      • 追查安装来源：pm list packages -i 看 installer=；DuerShowOTA 的日志在 /data/data/com.baidu.duer.ota/files/{installer,ota}.log。
      • pm disable 对 PERSISTENT 应用无效：显示 enabled=2 但仍在运行，被 kill 后出现 Start proc ... for restart。只能用 .replace。
      • 由中文名查包名：busybox unzip -p <apk> resources.arsc | grep -a -o '<中文名>'。
      • 失败的 F-Droid 安装：APK 留在 /data/app/vmdl*.tmp/base.apk，可用 pm install 复现错误。
      • 反编译 quicken 应用：先把 vdex 里的 dex unquicken，再交给 jadx。Android 8.1 的 vdex010 格式：
        • 头部：magic, version, n_dex, dex_size, verifier_deps_size, quickening_info_size（各 4 字节），然后是 n_dex 个 4 字节 checksum，接着是 dex 本体。
        • quickening 段：最后 4 字节是映射表偏移；映射表是 (code_item_off u32, info_off u32)[]；每个 info 是 u32 size 加 u16[]。
        • 按指令顺序消费索引：quick 指令（0xe3..0xf2）还原为对应的 iget/iput/invoke 并写回索引；0x73 改回 0x0e；每个 NOP 消费 1 个索引（0xffff 表示真 NOP，否则和下一个索引一起还原为 check-cast）。
        • 最后重算 dex 头部的 sha1 和 adler32。
      • mount namespace：su -c mount 对应用不可见；要全局生效用 su -mm -c mount -o bind ...。
      • ssh 引号：ssh duos 'su -c "...$X..."' 里的 $X 会先被 Termux shell 展开。复杂操作写成脚本 → su -c "sh script.sh"，并加 set -e。
      • 模拟安装来源：用 su 2000（shell，targetSdk 27）。uid 0 没有对应的包，会走 Cannot get target sdk version 分支，不能代表真实场景。
      • PackageInstaller 跑在 uid 1000。

      网络与镜像

      • F-Droid：添加 https://mirrors.tuna.tsinghua.edu.cn/fdroid/repo，关掉官方源。
      • Termux：执行 termux-change-repo，选清华或中科大。
      • ADB：setprop service.adb.tcp.port 5555; stop adbd; start adbd；持久化用 setprop persist.adb.tcp.port 5555。
      • Magisk 授权：在超级用户页给 Termux 开启 root（当前已授权的 uid：10020、10025、10070、10071）。
