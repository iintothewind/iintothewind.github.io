      Algolia 调查笔记 + Hacker News Search API 实战解析

      整理日期：2026-08-04 调查范围：Algolia.com 商业搜索服务；HN Search API（hn.algolia.com）实测

      一、Algolia 是什么

      Algolia 是一家 SaaS 搜索服务商，提供托管式全文搜索引擎。核心模式：你把数据推给它，它建索引，你的应用通过 API 查询。卖点是速度（毫秒级）、相关性排序、开箱即用的前端组件。

      需要先区分两件事：

      • Algolia 商业产品：B 端服务，注册账号、建 index、调 API，按用量计费
      • HN Search API（hn.algolia.com）：Algolia 替 Hacker News 免费托管的公开搜索接口，任何人免 key 直接调，与商业账号无关

      二、Algolia 商业产品：使用场景

      典型使用场景：

      1. 站内搜索：电商（商品搜索/筛选）、文档站（全文检索）、博客（文章搜索）、社区（帖子/评论搜索）
      2. 搜索建议 / 自动补全：输入即出联想（Autocomplete）
      3. 相关性排序：可配置 ranking 规则（典型度、地理位置、自定义权重），比数据库 LIKE 强得多
      4. 多租户隔离：一套索引按租户过滤
      5. AI 相关：向量检索、语义搜索（商业化功能，按量收费）

      个人开发者/小团队常见用法：博客站内搜索（替代自写 SQL LIKE）、文档站搜索（替代 DocSearch 审核等待）。

      博客接入的两条路对比

      维度 自建账号调 API DocSearch（官方爬虫）
      谁灌数据 自己写 sync 脚本推 JSON Algolia 爬虫自动爬
      更新 文章变动要重推索引 每周自动重爬
      可用性 注册即用，无审核 要申请 + 等审核
      工作量 写 sync 脚本 + 改前端 通过后引 snippet

      三、Algolia 商业产品：服务情况

      免费层（Build 计划），来自官网 pricing 实测：

      • 每月包含一定量请求（按「搜索请求」计费单元），超出后按量付费（如 $0.60 / 1K 请求量级，具体档位以官网为准）
      • 有记录数/操作数限制，个人博客量级足够
      • 超出限制的 API：按量计费，不是直接封

      付费升级方向（官网 plan finder 实测提及）：

      • Core search：搜索基础体验，起步免费、可平滑升级
      • AI features：语义搜索、动态重排（Dynamic Re-ranking）、推荐（Recommend API）
      • Enterprise：更高规模、治理、高级支持

      API 形态（两条线，别只理解成"一个 API"）：

      1. 写数据：POST /1/indexes/{indexName}/objects — 把记录（JSON）推入索引
      2. 查数据：POST /1/indexes/{indexName}/query — 搜索查询

      前端可引官方组件 InstantSearch / Autocomplete（JS + CSS），自带输入框、高亮、分页 UI。

      两个 API Key：一个私有（写入用，只放服务端），一个公开（查询用，可嵌页面）。

      四、Hacker News Search API（hn.algolia.com）实例解析

      4.1 这是什么

      Hacker News 官方搜索，Algolia 免费托管。数据源是 HN 的 Firebase API 实时同步，近实时（实测返回的 updated_at 是当天）。无需 key、免费、公开，普通 GET 即用。

      文档页 hn.algolia.com/api 是 JS 渲染（curl 拿不到正文），端点和参数用 GitHub 源码核对的：

      • 仓库：github.com/algolia/hn-search
      • 路由（config/routes.rb）：namespace :api/v1 下 search / search_by_date / items/:id / users/:username

      4.2 核心端点

      Base URL：https://hn.algolia.com/api/v1/

      端点 作用
      GET /search?query=... 全文搜索，按相关度排序
      GET /search_by_date?query=... 按时间排序（新 → 旧）
      GET /items/{id} 单个 item（帖子或评论）+ 递归评论树
      GET /users/{username} 用户信息（karma、约 created、约延迟）

      4.3 关键参数

      • query — 搜索词
      • tags=story|comment|poll|job|ask_hn|show_hn — 内容类型过滤；author_{username} 按作者；story_{id} 某帖下评论
      • numericFilters=points>100、created_at_i>时间戳 — 数值/时间过滤（可组合，逗号分隔）
      • hitsPerPage / page — 分页
      • advancedSyntax — 高级语法（默认开启）
      • 返回字段含 _highlightResult（带 <em> 高亮标签，前端直接用）

      4.4 实测例子（2026-08-04 实调）

      例 1：基本搜索

      curl "https://hn.algolia.com/api/v1/search?query=llm&hitsPerPage=2"

      返回 JSON 含：title / url / author / points / num_comments / created_at / objectID / _highlightResult。命中项标题带高亮："value": "<em>LLM</em> Inevitabilism"。

      例 2：类型过滤 + 统计

      curl "https://hn.algolia.com/api/v1/search?query=rust&tags=story&hitsPerPage=1"

      nbHits: 59,157 — 全库匹配 "rust" 的 story 数；过滤生效。

      例 3：按时间过滤（最近 24h story）

      url = f"https://hn.algolia.com/api/v1/search_by_date?tags=story&numericFilters=created_at_i>{int(time.time())-86400}&hitsPerPage=3"

      返回 nbHits: 1,184（24 小时内有 1,184 个新 story），结果按时间倒序，数据实时。

      例 4：取帖子 + 评论树

      curl "https://hn.algolia.com/api/v1/items/44567857"

      返回帖子元信息 + children（递归评论数组）。实测该帖 1,773 分、124 条直接评论，children[0] 可拿到首条评论作者和正文。

      4.5 注意事项

      • 限速：源码有 IP 级限速逻辑（RATE_LIMIT_WHITE_LIST），低频测试没问题，高频批量抓会 429
      • 大帖响应体很大：上千评论的帖子全树返回很大，按需取
      • 免 key 免注册：适合做 HN 搜索工具、热点统计、个人 HN 阅读器

      4.6 典型用途

      • 追话题：/search?query=llm&tags=story → 相关帖列表
      • 看某人发言：tags=author_pg
      • 热点统计：search_by_date + numericFilters=created_at_i>... + hitsPerPage=1000
      • 完整评论树：items/{id}

      五、结论

      • Algolia 商业产品：注册即用的托管搜索，适合站内搜索/文档搜索，免费层个人够用；成本是写 sync 脚本 + 前端接入
      • HN Search API：独立于商业账号的公开接口，免费免 key，实时、稳定，做 HN 相关工具直接可用
